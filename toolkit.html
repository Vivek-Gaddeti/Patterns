Input size → complexity

Read the constraints before you think about the solution. Python manages roughly 10⁷ simple operations per second, and OA time limits are usually 1–4 seconds.

n up toMax complexityUsually means
10–12O(n!)Try every permutation (backtracking)
20–25O(2ⁿ · n)Every subset, bitmask DP
100–500O(n³)Interval DP, Floyd–Warshall, triple loops
1,000–5,000O(n²)2-D DP, nested loops over pairs
10⁵ – 10⁶O(n log n) or O(n)Sorting, heap, binary search, two pointers, sliding window, hashing

Most OA problems have n ≤ 10⁵. That single line rules out every O(n²) idea, which is often the strongest hint you'll get about the pattern.

OA input formats

Platforms either call your function (like LeetCode) or make you read the input yourself from standard input. Know both before test day.

Function style

CodeSignal, most HackerRank tasks, LeetCode. You fill in a function; the platform calls it.

def solution(nums, k):
    # return the answer, don't print it
    return ...

Full program (stdin)

Some HackerRank and company tests. Read everything fast, print the answer.

import sys
def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    nums = list(map(int, data[1:1 + n]))
    print(solve(nums))
main()
${ICON}

input() is slow for 10⁵ lines. Read everything at once with sys.stdin.buffer.read(), and print with one "\n".join(...) instead of many print calls.

Fixing a time limit exceeded

  1. Check the complexity against n. If n is 10⁵ and you have nested loops, no micro-optimisation will save you. You need a different pattern.
  2. Look for hidden O(n) inside loops: in list, pop(0), slicing, min(), string +=.
  3. Recursion: raise sys.setrecursionlimit, or switch DFS to an explicit stack. Deep recursion is also slow in Python.
  4. Memoise overlapping subproblems with @lru_cache(maxsize=None) or a dict.
  5. Avoid repeated work: precompute prefix sums, sort once, build lookup dicts up front.
  6. Fast I/O for stdin programs (see above).
